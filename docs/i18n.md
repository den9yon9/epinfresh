# i18n — 后端用户文案国际化

> 只翻译**终端用户可见**的服务端文案（API 错误 `message` / 限流 429 / 会话守卫 / 通知邮件）。
> 面向开发者的一律不译：OpenAPI `summary`/`description`、Elysia 校验错误、日志、`pay-mock-server` 模拟平台协议。

## 1. 模型：标记 + 提取（gettext 式）

英文源串**既是 key、也是默认回退**。用户可见文案必须用标记函数包裹，提取器扫描标记生成/校验 catalog：

```
源码:   i18n('Order not found')            ← 标记 = 唯一翻译入口
              │
      ┌───────┴────────┐
 运行时(按 locale 查表)   提取(scripts/i18n-extract.ts)
      │                    │
 API: 每请求 translator    catalog/en.json      (key 清单, 自动生成)
 邮件: 每用户 translator   catalog/zh-CN.json   (译文, 半自动)
```

- 未被标记的裸文案不会被翻译；漏标记由 lint 兜底（见 §5）。
- 命中 catalog 则返回译文，未命中回落英文源串——**漏译不崩**。

## 2. 三种出口，一个标记

| 出口                            | 位置                           | 拿到 locale 的方式                           | 标记形式                    |
| ------------------------------- | ------------------------------ | -------------------------------------------- | --------------------------- |
| API 控制器                      | `apps/*-api/src/routes/*`      | `localePlugin` 的 `derive` 每请求注入 `i18n` | `i18n('源串', params?)`     |
| 基础设施边界（会话守卫 / 限流） | `packages/session/src/*`       | 直接读 `context.request` 头                  | `translate(locale, '源串')` |
| 通知邮件                        | `apps/worker/src/templates.ts` | `createTranslator(userLocale)`               | `i18n('源串', params?)`     |

`localePlugin`（`packages/http/src/localePlugin.ts`）只做一件事：把请求语言解析出来后注入绑定语言的 `i18n`：

```ts
export function localePlugin(options: { defaultLocale: Locale }) {
  return new Elysia({ name: 'i18n-locale' }).derive({ as: 'global' }, ({ request }) => ({
    i18n: createTranslator(resolveRequestLocale(request, options.defaultLocale)),
  }))
}
```

控制器用法（route 工厂里 `.use(plugins.localePlugin)` 后即生效）：

```ts
return result.match(
  (order) => order,
  (e) => {
    switch (e) {
      case 'ORDER_NOT_FOUND':
        return status(404, { error: e, message: i18n('Order not found') })
      default:
        return assertNever(e)
    }
  },
)
```

## 3. 语言协商

优先级：**`X-Locale` 头 / `?lang=` 查询 → `Accept-Language`（q 值降序）→ env `DEFAULT_LOCALE`（默认 `en`）**。
归一化：`en*` → `en`，`zh*`（`zh` / `zh-Hans` / `zh-CN`）→ `zh-CN`。
实现见 `packages/i18n/src/locale.ts`（`resolveLocale` / `normalizeLocale`）。

## 4. catalog 与工具

```
packages/i18n/src/catalog/
  en.json      key 清单（源串 → 源串），由提取器生成，勿手改
  zh-CN.json   英文源串 → 中文译文（人工维护/补译）
```

```bash
pnpm i18n:extract   # 扫描标记 → 重写 en.json + 合并 zh-CN.json（保留既有译文, 不清除陈旧译文）
pnpm i18n:check     # 只校验: 漏译 / 陈旧 / 标记非字面量 → 退出码 1
```

`i18n:check` 已接入 **lefthook pre-commit** 与 CI 门禁。

**新增/修改文案的流程**：

1. 在源码写标记，用英文源串：`i18n('Some new message')`。
2. `pnpm i18n:extract` —— en.json 出现新 key，zh-CN.json 补一条空值。
3. 在 `zh-CN.json` 填中文译文。
4. 提交时 `i18n:check` 校验通过（未填译文会被拦下）。

## 5. 强制约束（编译期/lint/提交期）

| 机制            | 规则                  | 作用                                                                |
| --------------- | --------------------- | ------------------------------------------------------------------- |
| eslint          | `i18n/marker-literal` | 标记实参必须是字符串字面量（否则提取器扫不到）                      |
| eslint          | `i18n/no-cjk-literal` | 用户可见面禁止裸中文字面量，兜底「忘标记」（OpenAPI `detail` 豁免） |
| eslint          | `i18n/no-core-import` | `domains/**`、`usecases/**` 禁止 import `@epinfresh/i18n`           |
| pre-commit / CI | `i18n:check`          | 漏译 / 陈旧 key 直接失败                                            |

规则实现见 `eslint-rules/i18n.js`（接入 `eslint.config.js`）。

## 6. 与分层的关系

**i18n 是呈现层职责**（你的判断）：`domain` / `usecase` 只返回错误码与数据，由控制器决定用哪种语言渲染成人话。
所以：

- `domains/*`、`usecases/*` 不得 import `@epinfresh/i18n`（编译期由 `i18n/no-core-import` 拦）。
- 邮件由 `apps/worker`（呈现层）渲染，locale 来自**用户偏好**而非请求头。
- `packages/session` 属基础设施边界适配器，产出 401/403/429 文案，允许用显式 `translate(locale, ...)`。

## 7. 邮件链路

邮件在 worker 异步渲染，没有 `Accept-Language`，用**用户语言偏好**：

1. `users.locale`（`varchar(16) default 'en'`，migration `0024`）。
2. 注册/登录时由 `resolveRequestLocale(request)` 落库；登录若语言变化则刷新。
3. 入队时 `SendEmailJobData.locale` 随任务走：welcome/reset 取自请求；交易类（支付/退款/发货）由 `usecases/notifications` 取 `users.locale`。
4. `renderEmail(template, vars, locale)` 内 `createTranslator(locale)` 渲染，模板文案全是 `i18n(...)` 标记。

## 8. 新增一种语言

1. `packages/i18n/src/locale.ts`：`SUPPORTED_LOCALES` 加语言 + `normalizeLocale` 加分支。
2. 新建 `packages/i18n/src/catalog/<locale>.json`（空对象即可）。
3. `packages/i18n/src/translate.ts`：`CATALOGS[locale]` 注册 import。
4. `scripts/i18n-extract.ts`：`TARGET_LOCALES` 加该语言。
5. `pnpm i18n:extract` 生成骨架 → 补译 → `pnpm i18n:check`。

路由与模板零改动。

## 9. 明确不做

- OpenAPI `/docs` 的 `summary`/`description`（面向前端开发者）。
- Elysia 请求校验错误文案（`VALIDATION`）。
- 日志、`pay-mock-server` 模拟平台协议。
- 商品/分类等内容数据翻译（DB 内容，非服务端文案）。
